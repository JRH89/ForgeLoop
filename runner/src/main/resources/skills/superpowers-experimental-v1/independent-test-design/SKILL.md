# Independent test design
Derive tests from the specification, acceptance criteria and public interfaces rather than copying an implementation's interpretation. Exercise the observable success case and meaningful rejection, boundary and isolation cases. Keep tests within assigned test paths and preserve existing tests. Tests should demonstrate the requested behavior, not mirror private implementation details.
Honor ForgeLoop's RED/GREEN protocol. New tests must compile and execute against the permitted baseline and fail on behavior assertions; missing dependencies, import errors, skipped tests or broken setup are not valid RED evidence. If new interfaces are required, the planner's scaffold protocol owns them. Do not write production implementation from a test-only task, forge reports, change expected behavior to match a defect, or claim a test ran without evidence.

Import and execute the real production modules, exported functions, or public application entry points under test. Never copy filtering, sorting, rendering, validation, or other production behavior into test-local replacement functions or components: such tests cannot detect defects in the application. Fixtures must be minimal, internally consistent, and checked against the specification; assert ordering and expected matches from their actual values. If a required public interface does not exist, report the scaffold prerequisite instead of fabricating a local implementation. On retries, preserve this independent test procedure and test-only boundary while correcting the bounded failure context.
